# 跟進 @fanny55520＝核對

用戶 11/27：「我是要你找出規則，不是要你照抄」「之前給你貼文是要你去核對」。
所以：**不要為了一篇貼文改程式、不要把她的數字寫進程式**。網站的推演引擎 `wave/scenario.py`（B131／B132）只看轉折自己算；
她的貼文是考卷（`research/b131/key.json`），拿來核對引擎、找出規則哪裡不夠。舊的樣板（stock_wave.py 的 B123～B130「她 M/D」）
留著當「舊版」跟引擎並排顯示，不再加新的樣板。

## 1. 讀懂貼文、加進考卷
- 截圖逐張讀，把**功能性價位**抄下來：關卡、防線、區間、目標、失效價。她的成交價、純粹描述走勢路徑的轉折不收。
  區間寬 ≤1% 當區間、>1% 拆兩點。同一天早上／盤中／夜盤分開。
- 判斷她發文時看得到哪些資料（cut，台灣時間）：晚上、夜盤的算到 23:00；週末算到週六 06:00；盤前 08:30；其他看發文時間（「N 小時前」往回推）。
- 加到 `research/b131/key.json` 的 `posts` **尾巴**（id 接下去），**不改舊的**。先 commit 考卷，再跑引擎。

## 2. 核對
- 要的資料：台指期日 K、5 分 K。雲端連不到 FinMind／期交所 → 用暫時 workflow 跑 `research/b131/fetch.py`（範本：`git show 8a2a8e6`），
  資料放 `research/b131/data/`（gitignore），用完刪 workflow。
- 跑 `python research/b131/run_b132.py`（整份考卷重跑；新貼文是**樣本外**，另外列出來）。
- 也可以存一份線上快照（`ship` skill），看網站的「🤖 引擎（新）」那一行和「🆚 新舊對照價位梯」。

## 3. 回覆用戶（用中文）
- 她這篇的重點（條列、帶數字）。
- 引擎在她發文那一刻自己算的：命中她幾成（±0.1%）、同樣距離隨便挑幾成；她的哪幾條引擎有、哪幾條沒有。
- 漏掉的原因分類：結構選錯（換組）、級數（月線／15 分）、轉折門檻太粗、她用量／籌碼／盤感（規則裡沒有）。
- 引擎的白話判斷跟她的定位一不一樣（例：她說「先當大 B 波」，引擎說「S2 過了重疊線、還沒到第二道牆」）。
- 不要灌水；累積的樣本外命中率要一起報。

## 4. 要改規則的時候
- 不是看一篇就改。累積到明顯的漏（同一種原因漏好幾篇），另外寫 `PLAN-Bxx.md` 把新規則寫死 → 改 `wave/scenario.py`（加新版本參數 v，舊版要能重現）
  → **整份考卷重考**，報告寫明哪些規則是「看到漏才加的」（樣本內）。
- 判方向、挑重點線目前都是 △（B131 考卷 B、B132）；要拿來當交易訊號先用 `backtest-research` skill 測。
