# 跟進 @fanny55520

她在 Threads 用波浪理論分析台指期（60 分、日線、多層浪名、黃金切割關卡）。用戶希望網站「越來越像她」，但網站是程式，學得到她的**框架**，學不到她看盤的判斷——所以做法是：把她的規則寫成可以算的東西、候選版本都列出來、用價位裁決；有回測的才標 ✅，沒有的標 △。

## 1. 讀懂貼文
- 截圖逐張讀，把**數字**全部抄下來：轉折點價位、浪名（例：C-1-4-b、3-2-c、(1)～(5)）、關卡區間、目標 T1～T3、防守價、失效價、她說的條件（例：「60 分收盤守住」「帶量實體紅 K 站穩」「第二隻腳 0.382～0.5 才做多」）。
- 分清楚她是在**定位**（現在是第幾浪、有哪幾個版本）、**畫關卡**（站上／跌破代表什麼），還是**給操作**（哪裡進、停損、走一口留一口）。

## 2. 對照網站現在的輸出
- 雲端連不到正式站：用 `ship` skill 的線上快照 workflow 存一份 `/api/wave` 快照下來，跟她的數字逐項比（轉折點、主要劇本、關卡、目標）。
- 找出差距的原因：是轉折點沒抓到（θ 門檻）、級數不同、版本排序不同，還是根本沒有這個概念。

## 3. 改哪裡
- 數浪核心（純函式）：`wave/engine.py`（轉折、數浪、失效、目標）、`wave/nest.py`（多層浪名、兩種走法、三種細微脈動、大中小、雙版本）、`wave/levelmap.py`（價位梯、如果…就…）。
- 組合快照：`wave/service.py`（例：`_tiers` 兩道關卡、`_pulses_mid`）；前端 `regime-frontend/wave.js`（劇本分頁的方塊），改完 `node --check`，並更新 `regime-frontend/index.html` 的 `wave.js?v=`。
- 個股：`stock_wave.py`（同一套方法用在日 K 兩個級數）→ `server.py` 深度分析、`deep_ai.py` 的資料段、`dashboard.html` 的 🌊 波段結構區塊。
- 上課筆記：`notes-frontend/notes.js` 波浪分類（`cat: 'w'`）那張她的時間軸卡片，`pts` 加一行「<b>日期</b>：她的重點」，必要時加新卡片；更新 `dashboard.html` 的 `notes.js?v=`。
- AI 圓桌規則（`wave/panel.py` 的 `RULES`）只放回測過的結論。

## 4. 測試
- 新增 `tests/test_bxx_*.py`：用合成的價格序列重現她貼文裡的轉折點，斷言網站算出的浪名、關卡、目標跟她的數字一致（容許小數四捨五入）。檔頭 docstring 寫她那天的重點，之後的人才知道在測什麼。
- 舊測試的期望值如果因為新規則變了，先確認是真的變好（例如她的寫法），再改期望值，不要為了過測試硬改。
- `python -m pytest tests -q` 全部要過。

## 5. 文件、部署、回覆
- 根目錄 `PLAN-Bxx.md`（編號＝CHANGELOG 最上面的下一號）寫：她說了什麼、網站原本怎樣、改了什麼、還做不到什麼。`CHANGELOG.md` 加一段 `fix＋feat: …跟進 @fanny55520 M/D…（Bxx）`。
- 照 `ship` skill 合併部署。
- 回覆用戶：她的重點（條列、帶數字）→ 網站改了什麼、在哪個分頁看 → 還不一樣的地方和原因。用戶問「像幾成」時，分項說（轉折點、浪名定位、關卡、目標、操作建議）哪些一致、哪些不一致，不要灌水。
- 她的進場方法如果要當交易訊號，先用 `backtest-research` skill 測過（B94d 已經測過「照程式數的浪自動進出」沒有比隨機好）。
